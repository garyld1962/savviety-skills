# Spec Review Adversarial Workflow

Use this to challenge a PRD, plan, or specification before implementation.

## Lenses

- Product: missing user outcome, scope creep, unclear acceptance.
- Engineering: hidden dependencies, impossible sequencing, weak verification.
- Risk: security, migration, data loss, privacy, rollback, operability.

## Output

- `Verdict`: `PASS`, `CONTESTED`, or `REJECT`.
- Findings ordered by implementation risk.
- Required spec changes.
- Questions that must be answered before execution.

Use `references/aers-readiness.md` for readiness criteria.
